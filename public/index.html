Centralised Data Access and Leakage Prevention

One place to manage who can release customer data, under what conditions, and with whose approval.

Local demonstration · Demo CRM data used · Controls only exports made through this application( there is no external database). It cannot stop screenshots or exports from other applications.

Sign in

Copy a password from the server terminal. Each restart generates new demo passwords.

Current export policy

Role and classification checks run on the server. A destination is a declared purpose; this demo downloads a CSV locally and does not send it anywhere.

Demo CRM customers

Staff see masked email addresses. Sensitive emails are masked in the customer view for all roles.

Export approval requests

Requests expire after 10 minutes. Approved downloads are single use. Change the policy and all open approvals become invalid.

IT policy configuration

Changes take effect immediately for all accounts.

Audit trail

Most recent first; latest 500 events saved in audit-logs.json. No passwords or customer email values are logged.

How the demonstration works

Staff / Manager→Authenticated request→Server policy check→Allow · Deny · IT approval

IT administrators configure shared rules and review the audit trail. The fictional CRM represents one application connected to a central governance layer.
